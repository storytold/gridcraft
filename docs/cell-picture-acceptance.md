# Native Excel acceptance: cell pictures and dynamic arrays

This protocol separates package acceptance, feature availability, recalculation,
and preservation on save for [#2339](https://github.com/storytold/gridcraft/issues/2339).
GridCraft opening its own output is a useful control, but does not establish
that Excel accepts the package. Conversely, a displayed error is not evidence
that Excel repaired or rejected it.

Before changing the writer, check the issue discussion and existing work:
[#1533](https://github.com/storytold/gridcraft/pull/1533) covers picture packaging
and scalar formulas; [#1571](https://github.com/storytold/gridcraft/pull/1571)
covers rich errors. Validate the actual head being reviewed separately from any
experiment that changes only selected XML attributes.

## Controls

Generate four workbooks from the same checkout and settings. Use an original,
locally generated PNG, never an issue attachment or linked reproduction file.
Keep reference-app saves and screenshots under gitignored `plan/excel/`.

| Workbook | B2 | D1 | D2:D3 | F1 |
| --- | --- | --- | --- | --- |
| Ordinary | Empty | Empty | Empty | Empty |
| Dynamic only | Empty | `=SEQUENCE(3)` | Spill: 2, 3 | `=SUM(D1:D3)` |
| Picture only | In-cell PNG | Empty | Empty | Empty |
| Picture + dynamic | Same in-cell PNG | `=SEQUENCE(3)` | Spill: 2, 3 | `=SUM(D1:D3)` |

Put the workbook's name in A1, a fixed text marker in A3 and the number 42 in
A5. This distinguishes content loss from the picture or formula's behaviour.
The existing CLI creates these through normal engine commands, for example:

```sh
cargo build -p gridcraft-cli
target/debug/gridcraft-cli run \
  --cmd 'cell.set={"cell":"A1","input":"picture-and-dynamic"}' \
  --cmd 'cell.set={"cell":"A3","input":"Owned synthetic control"}' \
  --cmd 'cell.set={"cell":"A5","input":42}' \
  --cmd 'insert.picture={"placement":"cell","at":"B2","path":"plan/excel/owned.png","alt":"Owned synthetic picture"}' \
  --cmd 'cell.set={"cell":"D1","input":"=SEQUENCE(3)"}' \
  --cmd 'cell.set={"cell":"F1","input":"=SUM(D1:D3)"}' \
  --out plan/excel/picture-and-dynamic.xlsx
```

For each run, replace the A1 input and `--out` path as listed below. Omit the
picture command and/or both formula commands according to the control matrix.
These distinct paths retain all four outputs for comparison.

| Control | A1 input | `--out` path |
| --- | --- | --- |
| Ordinary | `ordinary` | `plan/excel/ordinary.xlsx` |
| Dynamic only | `dynamic-only` | `plan/excel/dynamic-only.xlsx` |
| Picture only | `picture-only` | `plan/excel/picture-only.xlsx` |
| Picture + dynamic | `picture-and-dynamic` | `plan/excel/picture-and-dynamic.xlsx` |

Record the source commit and fixture hashes. Generate an independent set from
each candidate PR head when comparing implementations. An edited package that
contains only a PR's metadata changes is an **isolated packaging experiment**,
not acceptance testing of the whole PR.

## Native procedure

1. Record the platform, Excel version/build, licence, UI language, calculation
   mode and relevant feature availability. Verify that this edition can insert
   a picture **in a cell**; floating pictures do not establish that capability.
2. Open each original fixture independently. Record no prompt, repair prompt,
   or refusal. If offered a repair, record the original outcome before proceeding
   and retain any repair report locally. Do not silently replace the original.
3. Check A1/A3/A5; inspect B2 visually and in the formula bar. For dynamic cases,
   check D1:D3 = 1/2/3 and F1 = 6. Record the actual error text if present. An
   unsupported picture feature and a malformed package are separate findings.
4. Recalculate and repeat the checks. Cached spill results alone do not prove
   that Excel can calculate the formula. Record the calculation action used.
5. Save As a new local XLSX, close it, reopen the saved copy and repeat the
   content checks. Reopen that copy with GridCraft too. Inspect picture bytes,
   formula/metadata and errors separately; a successful Save As can still lose
   unsupported content.
6. Close test documents and quit Excel. Discard only disposable test changes;
   preserve unrelated user documents and unsaved work.

Record each stage independently: open outcome, feature rendering, recalculation,
native save/reopen, and GridCraft reimport. Leave unavailable stages explicitly
untested. Mac observations do not establish Windows or web acceptance.

## Mac observations

On 2026-11-08, Excel for Mac 16.114.4 (26110224), Office Home & Business 2021,
French UI, automatic calculation mode, produced the following results. The
four controls were generated by GridCraft's CLI; the tested writer matches
`2c58c769` for `richdata.rs` and `write.rs`. The original picture was a locally
generated 40 by 20 RGB gradient.

| Input | Open outcome | Observed content |
| --- | --- | --- |
| Ordinary | No repair prompt | Text markers and 42 retained |
| Dynamic only | No repair prompt | D1:D3 = 1/2/3, F1 = 6, markers retained |
| Picture only | Recovery prompt; accepting recovery reports removed/repaired content | B2 displays `#VALEUR!`; markers retained |
| Picture + dynamic | Same recovery prompt/result | B2 displays `#VALEUR!`; D1:D3 = 1/2/3, F1 = 6, markers retained |
| Picture only, metadata experiment | No repair prompt | Gradient visible in B2; markers retained |
| Picture + dynamic, metadata experiment | No repair prompt | Gradient, spill values, sum and markers retained |

The isolated experiments apply these four changes from PR #1533 to the owned
main-output fixtures, leaving all other package content intact:

- Lowercase `rdRichValue` in its content type to `rdrichvalue`.
- Lowercase `rdRichValueStructure` in its content type to `rdrichvaluestructure`.
- Lowercase the rich-value extension URI
  `{3E2802C4-A4D2-4D8B-9148-E3BE6C30E623}`.
- Change the `XLRICHVALUE` metadata-type suffix from `assign="1" cellMeta="0"`
  to `assign="1" coerce="1"`.

This tests the changes together, not the necessity of each individual change.
It is not a build or validation of the entire #1533 or #1571 implementation.
The tested edition demonstrably renders these in-cell pictures; its licence
name alone would have been a poor proxy for that capability. Native insertion
of a new in-cell picture was not tested.

The dynamic-only workbook survived Save As, close and reopen without a repair
prompt, preserving the spill and sum. The combined metadata experiment also
survived Save As to a separate XLSX, Formulas → Calculate Now, save, close and
reopen: the picture, 1/2/3 spill, sum 6 and markers remained. The reopened sheet's
accessibility data identified D1 as a three-row spilled formula, D2/D3 as its
spill values, and B2 by the picture's original alternative text. The saved
package retained the original PNG bytes exactly. GridCraft's CLI reopened that
saved copy and retained formula values; its text output uses the picture's
`#VALUE!` fallback, which does not establish picture rendering.

The repaired main-output workbooks were closed without saving over the
originals. Excel was quit after testing. No Office-produced files or screenshots
are part of this contribution. Defined names, rich `#SPILL!`/`#CALC!` errors and
the full PR heads remain untested. These Mac observations support the existing
packaging approach without establishing Windows or web acceptance.
