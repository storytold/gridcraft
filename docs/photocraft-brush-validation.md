# Experimental PhotoCraft Brush validation

This report describes the Windows prototype based on GridCraft 0.19.1 at `37941f06244565bdc91d32394d74fb9b0e48fae4`, with PhotoCraft's CPU renderer pinned to `74330157cb601573ae4523a95bb9132822fc3918`. The Windows v3 build includes the brush-panel fix. This is an experimental idea for maintainers to evaluate, reshape, continue, or close.

## Drawing scale and brush controls

The adapter keeps raster pixels separate from worksheet coordinates. Worksheet zoom uses the normal picture transform. Adaptive rendering records its pixels-per-unit value so a long stroke keeps its worksheet size. Restyling reconstructs the stroke's sheet origin and resize scale from its current picture anchor. These changes address drawing scale within the prototype.

The exposed controls are preset, color, size, hardness, opacity, flow, smoothing and pressure-controlled size. The adapter passes them to PhotoCraft. Hard round, Soft round, Chalk and Highlighter are available. Selecting a different preset loads its defaults. Existing strokes are restyled explicitly with **Apply to selected stroke**.

The v2 dropdown reproduced an interaction failure. Opening its nested preset list displaced the brush panel's popup, and the next stroke still used Hard round. V3 places preset choices directly in the panel and expands the color picker in place. Automated mouse input selected all four presets in the Windows executable and recovered the expected preset from each subsequent stroke. The same flow changed the stored color from RGB 31,95,201 to RGB 96,103,130.

## Long strokes

The original Windows build accepted a 900-unit horizontal stroke but rejected a diagonal with the same width and a 650-unit vertical span. Both used two samples. The padded bitmap at two pixels per worksheet unit exceeded the 1.5-million-pixel budget.

The renderer now chooses the highest resolution that fits the dimension, pixel and work budgets. Preview and commit use the same scale. The drawing keeps its original worksheet size and pointer samples. The normal resolution is two pixels per worksheet unit. Long strokes may look softer at high zoom. If a gesture reaches a remaining limit, GridCraft saves the accepted portion.

## CPU measurements

AMD Ryzen 5 5600, Windows x64, optimized Cargo development profile. The harness used one warm-up and 12 measured passes per case. Preview timings include sample ingestion and RGBA generation. Commit timings include the completed render and PNG encoding. Display, input delivery, workbook saving and GPU upload are outside these timings.

| Stroke | Old preview p95 | Fixed preview p95 | Old commit median | Fixed commit median | Fixed commit p95 |
|---|---:|---:|---:|---:|---:|
| Soft round, 320 × 130 units, 121 samples | 0.39 ms | 0.38 ms | 8.37 ms | 8.05 ms | 8.58 ms |
| Hard round, 1,500 × 800 units, 241 samples | Rejected | 3.58 ms | Rejected | 37.06 ms | 38.05 ms |
| 64-unit Chalk, 1,500 × 800 units, 241 samples | Rejected | 2.59 ms | Rejected | 9.68 ms | 12.83 ms |

The long strokes produced 72,636-byte and 75,949-byte PNGs including editable stroke data. Their slowest measured preview updates were 10.34 ms and 4.56 ms. The short test produced a 61,820-byte PNG in both versions.

Run `cargo run --locked -p gridcraft-brush --example brush_benchmark` to repeat the three scenarios.

## File formats and Excel

These checks used a generated workbook containing five drawings covering all four presets and a long Chalk stroke saved at one pixel per worksheet unit.

| Format | Observed behavior |
|---|---|
| XLSX | GridCraft saved five drawings. Desktop Excel displayed all five as pictures. |
| XLSM, XLTX, XLTM | Each file reopened with editable stroke data in GridCraft. Desktop Excel found all five pictures in each file. |
| GridCraft JSON | Reopened with editable long-stroke data. |
| PDF | The complete long stroke and four short marks were visible in GridCraft's PDF and a PDF rendered by Excel from the XLSX. |
| HTML | Export contained five embedded PNG images and the worksheet text. |
| CSV, TSV | Worksheet text was preserved. These formats carry cell data only. |
| XLS, XLSB, ODS, SLK | GridCraft offers these formats for import only. |

Excel saved a separate XLSX copy. SHA-256 checks showed that its five PNGs were byte-identical to the originals. GridCraft reopened that copy, recovered the presets and restyled the long Chalk stroke. This used Excel's default picture settings. Recompressing or replacing a PNG can discard private brush metadata.

The file and Excel checks ran on the v2 Windows executable. V3 changes the brush panel, with each preset and a custom color verified through the native app. The sample workbook was generated by GridCraft.

## Module boundary

`gridcraft-brush` owns GridCraft settings, samples, PNG metadata and the renderer adapter. Only the renderer module calls PhotoCraft. The engine and UI use GridCraft types. The PhotoCraft dependency revisions are pinned together and the lockfile is committed. A PhotoCraft desktop update cannot replace this compiled dependency. An intentional source upgrade still needs rendering, file, UI and web checks.

Each stroke is a transparent PNG picture with versioned private `gcBR` metadata. Unsupported source versions retain the readable PNG fallback. The normal image tools handle move, resize, deletion and print. Commit and restyle use the normal undo system. The picture cache also invalidates when restyling or undo replaces an image with different bytes of the same length.

The adapter bounds samples, bitmap dimensions, pixel area and estimated work. It chooses 2, 1, 0.5 or 0.25 pixels per worksheet unit and replays the live samples only when crossing a resolution threshold.

## Scope requiring further evaluation

- Excel displays strokes as pictures. Its native ink tools do not edit the PhotoCraft samples. GridCraft restyling requires the private PNG data.
- File checks cover a generated sample and one desktop Excel installation. Other viewers and Excel picture-compression settings need broader checks.
- CPU timings cover three gestures on one computer. Large workbooks, many drawings and sustained drawing need profiling.
- Very large strokes can look softer at high zoom. Gestures beyond the remaining limits commit their accepted portion and show a status message.
- Physical tablets, driver pressure, native tilt, eraser ends and multi-monitor DPI need validation. The input bridge uses force where egui supplies it. Accepted automation tilt fields do not establish native tilt capture.
- The prototype exposes four presets. Imported PhotoCraft/ABR brush libraries and full PhotoCraft feature coverage require further work.
- The download is an unsigned portable Windows x64 optimized development build. Native runtime validation on macOS and Linux remains open.

## Verification status

The five renderer tests, four engine brush tests and four UI brush gesture tests passed on the publication source. They cover settings changing pixels, preview/commit parity, the long diagonal, XLSX persistence and undo, origin preservation across rendering resolutions, moved/resized stroke scale, and preset selection through the Draw ribbon. The pressure and cancellation checks use synthetic input.

Focused Clippy passed with warnings denied for `gridcraft-brush`, `gridcraft-engine` and `gridcraft-ui-egui`, including all their targets. Formatting, asset attribution, dependency layering and generated parity/keytip checks passed. The GNU engine test executable was linked with the toolchain's current `libuser32.a` to provide the Windows DPI symbols.

`cargo xtask wasm` passed its compile check for all 14 packages, including the brush adapter and web app. Browser runtime behavior still needs validation.

A full `cargo xtask ci` attempt stopped at Clippy. That run reported a compiler exit in dependency `cms 0.2.3` and prototype lint findings. The prototype findings were corrected and the focused Clippy run passed. The full workspace test suite and doctests remain unverified.

Useful focused commands are

```sh
cargo test --locked -p gridcraft-brush --test render
cargo test --locked -p gridcraft-engine --test it brush_roundtrip::
cargo test --locked -p gridcraft-ui-egui --test it brush_gesture::
cargo clippy --locked -p gridcraft-brush -p gridcraft-engine -p gridcraft-ui-egui --all-targets -- -D warnings
```
