# ODBC Data Connections Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. Execution is authorized by the user's instruction to implement and commit in English.

**Goal:** Import and manually refresh PostgreSQL query results through Windows ODBC from the desktop, CLI and MCP commands.

**Architecture:** A toolkit-independent ODBC crate returns bounded typed results. Engine jobs run native calls off the UI thread and apply results through an undoable command. Tables own source definitions; XLSX/JSON preserve definitions without credentials. Existing non-Windows and WASM builds keep working without native ODBC dependencies.

**Tech Stack:** Rust 2024, safe odbc-api interfaces, serde, egui, existing engine COW transactions.

**Spec:** `docs/superpowers/specs/2026-10-13-odbc-design.md`

## Global Constraints

- Windows desktop/CLI first; PostgreSQL is the first supported database; native driver integration verification requires a registered psqlODBC driver.
- No unsafe or production panics. No driver dependency on WASM.
- 100,000 rows; 256 columns; 128 MiB materialized data; 1 MiB per cell. Preview at most 100 rows.
- Login timeout 15 seconds; query timeout 60 seconds, subject to driver support.
- No automatic execution on workbook open and no secrets in persisted definitions or journals.
- Atomic, undoable load/refresh; cancellation prevents applying results.
- English source documentation and English commit messages.
- Run `cargo xtask ci` before commits; collect changes into independently reviewable commits after this gate.

## Review Focus

1. Database text beginning with `=` must remain text after import and XLSX reopening (Task 3 tests).
2. Decimal/bigint values outside Excel's precision must remain exact text (Task 1 tests).
3. A query finishing after document changes/cancellation must not write to another document (Task 3 tests).
4. Nested secrets and diagnostic messages must not leak through saved scripts or files (Tasks 1–3 tests).
5. Refresh must not destroy adjacent cells, formulas, or locally changed query data (Task 3 tests).

## ODBC.2: additional database adapters (2026-10-15)

- The user requested other popular databases and explicitly authorized implementation, tests and the contribution CI. Scope: SQL Server/Azure SQL, MySQL, MariaDB, Oracle and SQLite3 alongside PostgreSQL, through the existing commands and UI.
- Driver profiles identify the installed driver from a registered DSN or DRIVER selector before connecting, then verify the DBMS. MySQL and MariaDB accept either compatible server. Ambiguous/file selectors are rejected; braced values and credential aliases are handled without persisting credentials.
- Each family supplies its own options, test SQL and transaction setup. SQL Server relies on SELECT-only server permissions; its read intent is not write protection. PostgreSQL retains its cursor wrapper; other families preserve the original query syntax.
- Native query guards use the Apache-2.0 sqlparser tokenizer with the selected dialect, rejecting write/control keywords and executable comments. This is not a function sandbox. The dependency is Windows-only; portable and WASM interfaces are unchanged.
- Test-first checkpoints observed the missing profile APIs and type-mapping helper before implementation. All eleven connector unit tests then passed, covering profiles, escaping, selectors, dialects, vendor types, precision and limits.
- Five additional opt-in integration tests cover synthetic results, Unicode, exact integers, NULLs, empty results, overflow, previews and cancellation. No live connection was supplied; they remain ignored, alongside the existing PostgreSQL integration test. No vendor binaries were installed or bundled.
- A fresh read-only review found no material correctness issues. Its tracing documentation caveat was corrected: vendor/ODBC manager tracing is configured separately.
- Full `cargo xtask ci` passed all eight gates: 1,625 tests passed, zero failed, seven ignored (six native ODBC integration tests and the existing opt-in soak test). WASM remains compatible; catalog parity is unchanged at 275/291.
